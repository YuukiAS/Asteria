# 统计实现追踪的补充实例与待办

日期：2026-09-15。
状态：远期设计素材；不实现产品，不改2.0模式或界面，不是当前稳定版阻断项。

本笔记补充 `2026-09-15_asteria_github_code_trace_todo.md`，保留其中“科学语义图、代码图、绑定层分开”的方向。下面均为通用设计例子，不是任何私有科研项目的实际代码、数据或结果。示意函数尚未实现，不能在界面中标成已核实绑定。

## 1. 不只是回答变量在哪里

研究者点击一个量以后，往往需要知道它在代码中的角色：它是读入的数据、待估参数、固定计算设置、派生值，还是一次随机抽样？同一个量还可能有“自然尺度”和“优化自由坐标”两种存储，甚至已被积分消去而没有逐项数组。

未来代码追踪应把这些角色连起来，而不是只返回搜索命中的变量名。绑定存在不证明实现正确，测试通过也不等于模型定理成立。

## 2. 有价值的实例

| 研究者的问题 | 应展示的实现关系 | 必须避免的误导 |
|---|---|---|
| 分组数据怎样影响共享均值？ | 数据读取、似然消费、共享参数更新、预测读取的局部路径 | 把函数调用箭头画成生态因果箭头 |
| 这个正参数为什么在代码里是另一个名字？ | 自然尺度、log坐标、逆变换、Jacobian所在函数 | 只找到log变量而漏掉密度变换 |
| 为什么找不到每一个匿名列的数组？ | 积分消元、原型与重数、目标函数中的加权贡献 | 没有逐列存储就判定该科学对象没实现 |
| 多个对象使用同一个数值函数，是否互相借力？ | 通用函数与各自先验/输入实例 | 把代码复用当作统计信息共享 |
| 哪个随机结果可以复现？ | 随机流角色、运行配置、独立链和断点状态 | 把确定性变换也标成随机，或仅展示一个seed数值 |
| 这个矩阵是哪里来的？ | 身份对齐、源字段、构造函数、矩阵类型及校验 | 分类相似度、树相关和残差相关混成一种C |
| 两套程序一致，为什么还可能一起错？ | 被测代码、独立参照及其依赖关系 | 两个包装调用同一底层函数却称独立验证 |
| 同一函数在另一个版本改了，数学含义一定变了吗？ | 代码差异、受影响绑定与待复核提示 | 自动宣布定理或科学主张失效 |
| 为什么两条后验路线要分开？ | 生产近似和独立参考采样分别绑定同一目标 | 用相同算法的另一包装当可靠裁判 |
| 一条链为什么很慢？ | 已批准的更新块、参数变换和实际诊断证据 | 仅凭调用图宣布混合已经改善 |

这些问题的答案应按实际证据显示完整或部分覆盖，不能由AI补全不存在的实现。

## 4. 测试与参照也需要分层

建议未来证据视图区分：解析恒等式、独立数值积分、同底层库的一致性检查、可靠采样参照、已知生成机制的模拟恢复、真实留出预测、历史快照。显示“验证了什么”，同时显示“没有验证什么”。

例如一个重数聚合测试只证明两种记账形式一致，不直接验证所使用的积分近似。一个采样函数存在，也不说明其链的有效样本量足够。Asteria不需要自行执行全部统计诊断，但应能把外部证据类型和依赖边界表达清楚。

## 5. 数据到代码的追踪需要覆盖预处理

代码绑定不应从fit函数才开始。可以局部追踪原始文件 → 身份键 → 训练/未来划分 → X或T尺度变换 → 模型对象。矩阵C的来源字段、物种顺序与矩阵校验属于数据派生过程，不应和模型中的随机相关参数混在一起。

完整源码扫描可能无法理解动态语言的调度与运行时对象。静态调用、开发者明确绑定和实际执行证据应标不同来源。缺少某一段时允许显示“未解析”，不根据名称相似猜成已确认。

## 6. 与实现过程的轻量反馈

未来科研实现每完成一个重要算法阶段，可补少量高价值实例，不要求每个辅助变量或每次格式修改都维护大型图。合适的实例包含：研究者的问题、科学对象、代码角色、经过核实的函数/版本、测试或参照、尚未覆盖的部分。

执行者只能记录已批准设计的实际落实与观察到的缺口，不在提交追踪资料时重新设计模型或Asteria。产品层仍需由规划者决定统一Schema、界面和索引策略。没有真实证据时记“暂无新实例”，不能为完成任务虚构代码绑定。
